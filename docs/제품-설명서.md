# 헬스반장(FitRoutine) 제품 설명서

> 이 문서는 외부 평가를 받기 위해 만든 제품 전체 설명서다.
> 2026-08-21 기준 **실제로 배포되어 돌아가고 있는 것**만 적었다.
> 계획 중인 것은 마지막 「아직 안 된 것」 절에 따로 모았다.

---

## 1. 한 줄 요약

**아파트 단지 안 헬스장에서, 40~60대 주민이 오늘 뭘 해야 할지 몰라 기구 앞에서 서성이지 않게 만드는 앱.**

---

## 2. 왜 만들었나

아파트 커뮤니티 헬스장에는 공통된 문제가 있다.

- 기구는 있는데 **어떻게 쓰는지 알려주는 사람이 없다.** 트레이너가 상주하지 않는다.
- 처음 온 사람은 기구 앞에서 눈치만 보다 러닝머신만 걷다 간다.
- 관리사무소는 **몇 명이 쓰는지 모른다.** 이용 실적이 없으니 예산을 못 늘린다.
- 헬스장 앱은 많지만 전부 20~30대 헬스인 기준이다. **글씨가 작고 용어가 영어다.**

헬스반장은 그 셋을 동시에 푼다: 개인에게는 **오늘의 운동을 정해주고**, 기구마다 **사용법을 붙여주고**, 관리사무소에는 **이용 통계를 준다.**

---

## 3. 누가 쓰나

| 사용자 | 기기 | 쓰는 방식 |
| --- | --- | --- |
| **주민 회원** | 자기 폰 | 웹 주소로 접속(설치 불필요) 또는 앱 설치 |
| **헬스장 태블릿** | 벽걸이/거치 태블릿 | 키오스크 모드 — 출석 체크, 기구 QR 안내 |
| **관리사무소** | (예정) | 월간 이용 실적 |

주 타겟은 **40~60대**다. 이 한 줄이 앱의 거의 모든 디자인 결정을 지배한다(§9 참고).

---

## 4. 회원이 겪는 흐름

### 4.1 처음 들어올 때

```
로그인 → 개인정보 동의 → 온보딩 설문 → 홈
```

**로그인** — 카카오 로그인이 기본이다. 40~60대가 이미 매일 쓰는 앱이라 아이디·비밀번호를 새로 만들 필요가 없다. 전화번호 인증, 이메일도 준비돼 있다.

**동의** — 설문에서 "아프거나 불편한 곳"을 묻는데 이건 건강에 관한 민감정보다. 그래서 **동의가 설문보다 반드시 먼저** 나오도록 화면 순서를 강제했다.

**온보딩 설문** — 다음을 묻는다:
- 이름 / 닉네임(랭킹에 노출되는 이름, 실명과 분리)
- 성별, 나이
- 키, 몸무게
- **아프거나 불편한 곳** (무릎/허리/어깨/목 등)
- 운동 목적, 주당 희망 횟수

### 4.2 매일 쓰는 흐름

```
홈(오늘의 운동) → 운동 하나 고르기 → 사용법 확인 → 하고 나서 기록 → 완료
```

## 5. 화면별 기능 (하단 탭 5개)

### 🏠 홈 — 오늘의 운동

- **인사말** + 그날의 응원 한 줄
- **상황 안내 칸**: "아프신 곳을 피해서 짰어요" 같은 한 줄 안내
- **오늘의 운동 목록**: 서버가 자동 생성한 3~5개. 각 항목에 기구 사진, 번호, 부위
- **바로가기 타일 3개**: 기구 사용법 / QR 찍기 / 스트레칭

**오늘의 운동은 어떻게 정해지나** — 서버가 매일 자동으로 짠다. 반영하는 것:
- 그 사람 나이·성별 (연령별·성별 보정치 테이블)
- **아프다고 한 부위** (해당 부위에 위험한 동작은 제외, 무게도 낮춤)
- **그 헬스장에 실제로 있는 기구만** (다른 데 있는 기구를 보여주면 찾으러 다니게 된다)
- 최근에 한 운동 (같은 부위 연속 방지)
- 지난번에 "힘들었어요" 를 눌렀으면 다음엔 낮춰서 제안

### 🏃 운동 상세 화면

기구를 고르면 나오는 화면. 세 종류로 갈린다.

**(a) 핀 방식 기구** (레그프레스 등)
- 시작 자세 사진 + 동작 순서
- "핀을 몇 칸에 꽂으셨어요?" → **숫자판(키패드)** 으로 입력
- 무게(kg)가 아니라 **칸 수**로 묻는다. 기구마다 1칸당 무게가 다르고, 어르신들은 "몇 kg" 보다 "몇 칸"을 기억한다

**(b) 맨몸 운동** (의자 스쿼트, 벽 팔굽혀펴기)
- 사진 + "오늘 하신 만큼 3세트 × 10회" + 세트 표시
- [힘들었어요 / 할 만했어요] 두 버튼으로 마침

**(c) 유산소** (러닝머신, 자전거)
- 시간 입력 후 마침

**공통 안내** — 모든 근력운동 뒤에 호흡·속도·휴식 규칙이 붙는다.
출처: **CDC/NIA 「Growing Stronger: Strength Training for Older Adults」** (미국 질병통제예방센터 발행, Tufts 대학 개발). 원문 규칙을 그대로 옮겼다.

### 📅 달력

- 월별 격자에 운동한 날 표시
- 날짜를 누르면 그날 무엇을 했는지

### 🏆 랭킹 — "화합의 장"

이 앱에서 **가장 공들인 부분**이다. 개인 순위 경쟁이 아니라 **단지 공동 목표**가 중심이다.

**이번 주 다 같이 (원형 게이지)**
- 단지 전체 주간 출석 목표를 원형 링으로. 링 끝에 **달리는 사람** 배지가 진행률만큼 이동
- 목표 = 활동 인원 × 2회 (최소 30명 기준). 유산소 목표 = 인원 × 30분, 무게 목표 = 인원 × 3000kg
- **요일별 막대그래프** — 각 요일 몇 명 왔는지 숫자가 막대 위에 뜬다
- **다 같이 걸은 거리(km)**, **다 같이 든 무게(kg/톤)** 를 목표 대비 막대로

**오늘의 응원 (게시판)**
- 이웃끼리 한 줄 응원 글. 이건 자유게시판이 **아니다**. 구조로 싸움을 막았다:
  - 하루 한 사람 **한 줄만**
  - **60자 제한** (긴 글은 논쟁이 되고 짧은 글은 응원이 된다)
  - **답글·좋아요 없음** (주고받기가 시작되면 관리가 필요해진다)
  - **이번 주 글만** 표시 (쌓여서 게시판이 되는 걸 막는다)
  - 닉네임만 노출, 실명 안 나감
  - 비속어 필터

**개인 랭킹**
- 범위 토글: **우리 단지 / 전체 단지**
- 기준 토글: **출석순 / 포인트순**
- 각 줄에 등급 배지 + 닉네임

### 📊 분석

- 기간 토글: 이번 주 / 이번 달 / 전체
- 완료·근력 세트·유산소 분 **큰 숫자 타일 3개**
- **부위별 막대** + "복부·팔은 이번에 쉬었어요" 같은 한 줄 해설
- **누적 기록**: 지금까지 걸은 거리(km), 든 무게(kg/톤)
- **몸무게 그래프** — 하루치만 있어도 점 하나 찍힌 틀을 보여준다("여기에 쌓인다"가 보여야 내일 또 잰다)

### 👤 프로필

- **등급 카드** — 7단계 호칭 체계
  | 등급 | 필요 경험치 |
  | --- | --- |
  | 새내기 | 0 |
  | 성실회원 | 300 |
  | 모범회원 | 1,000 |
  | 운동 고수 | 3,000 |
  | 운동 달인 | 7,000 |
  | 운동 9단 | 15,000 |
  | 천하장사 | 30,000 |

  경험치: 출석 +30 / 운동 완료 +10 / 그 주 3번째 출석 +50
  등급마다 **배지 그림이 다르다**(별·리본·왕관이 단계별로 붙는다)

- **국토 종주** — 유산소 누적 거리를 "서울 → 강릉" 여정으로 환산. 남양주·양평·홍천·횡성·평창·대관령·강릉 경포까지 구간마다 이름이 있다
- **글자 크기 조절** (앱 전체에 적용, 기기 바꿔도 유지)
- **운동 리마인더 설정** (끔 / 아침 8시 / 낮 12시 / 저녁 6시)
- 아픈 곳 정보 거두기(삭제), 계정 정보, 약관

## 6. 헬스장 태블릿 (키오스크 모드)

같은 앱이지만 **태블릿으로 열면 다른 모드**로 뜬다.

- **출석 체크**: 회원이 자기 번호를 숫자판으로 입력 → 출석 기록
- **기구 QR**: 기구에 붙은 QR을 폰으로 찍으면 그 기구 사용법 페이지로 바로 이동 (로그인 없이도 열린다)
- **페어링**: 태블릿과 폰을 QR로 연결
- 태블릿이 **자기가 어느 단지 소속인지 스스로 기억**한다

## 7. 기구 도감

- **75개 운동**에 사진과 동작 순서
- 사진 출처: free-exercise-db (퍼블릭 도메인, Unlicense) — 비용·저작권 문제 없음
- **우리 헬스장에 있는 기구만** 목록에 나온다 (없는 걸 보여주면 찾으러 다니게 된다)
- 맨몸 운동은 기구가 필요 없어 항상 나온다
- **스트레칭 8동작** 별도 페이지 (7개에 사진)

## 8. 데이터 구조 (주요 테이블)

```
users                    회원 (nickname 은 랭킹 노출용, 실명은 profile_data 안에 분리)
apartments               단지
user_gym_memberships     누가 어느 단지 헬스장을 다니는지 (이사하면 left_at 기록)
equipments               단지별 실제 보유 기구
exercise_catalog         운동 도감 75개 (사진, 동작 순서)
daily_routines           그날 자동 생성된 오늘의 운동
attendance_logs          출석
body_weight_logs         몸무게 기록
apartment_cheers         오늘의 응원 글
user_equipment_levels    그 사람이 그 기구를 몇 칸으로 하는지
age_modifiers            연령별 강도 보정
gender_modifiers         성별 강도 보정
pain_area_rules          아픈 부위별 제외/감량 규칙
user_consents            동의 이력
banned_words             비속어 필터 사전
device_pairings          태블릿-폰 페어링
```

**개인정보 설계**
- 랭킹·응원에 나가는 건 **닉네임뿐**. 실명은 별도 필드에 있고 서버가 응답에서 제외한다
- 닉네임은 **비속어 필터 + 2주에 한 번만 변경 가능**
- 아픈 곳 정보는 회원이 직접 **삭제 요청** 가능 (누르면 확인창을 한 번 더 띄운다)
- 모든 서버 함수는 권한 검사를 거친다 (RLS + security definer)

## 9. 설계 원칙 — 40~60대를 위해 실제로 한 것

이게 이 제품의 핵심 차별점이라 따로 적는다.

**글자와 손가락**
- 기본 글자 16px, 본문 줄간격 1.65 이상
- 모든 누르는 것 최소 56px (일반 앱 44px보다 크다)
- 앱 안에서 글자 크기를 3단계로 조절 가능

**한글 줄바꿈**
- 어절이 줄 끝에서 **중간에 잘리지 않게** 처리 (`word-break: keep-all`)
- **문장 단위로 줄을 넘긴다.** 한 줄에 앞 문장 꼬리와 다음 문장 머리가 같이 있으면 읽는 사람이 문장 시작을 눈으로 찾아야 한다
- 한 줄 길이를 560px로 제한 (너무 길면 다음 줄 머리를 못 찾는다)

**말을 줄인다**
- 화면에 이미 보이는 걸 글로 또 설명하지 않는다
- "아래에서 눌러 주세요 — 그걸로 마치기가 돼요" 같은 문장은 전부 삭제
- 물어볼 것 하나만 남긴다: "핀을 몇 칸에 꽂으셨어요?"

**용어**
- 영어·헬스 전문용어를 안 쓴다. "세트", "kg" 정도까지만
- 무게 대신 **칸 수**로 묻는다

**색**
- 빨강은 **진짜 오류에만**. 안내는 파랑. (빨간 바탕이면 읽기 전에 겁부터 먹는다)
- 되돌릴 수 없는 동작(삭제)에만 빨간 버튼

**숫자 입력**
- 키보드 대신 **큰 숫자판**. 한 칸이 130×70px

## 10. 기술 구성

| 항목 | 내용 |
| --- | --- |
| 앱 | React Native + Expo (expo-router) |
| 웹 | 같은 코드를 정적 번들로 빌드 → GitHub Pages (설치 없이 주소로 접속) |
| 서버 | Supabase (PostgreSQL 17) — 서울 리전 |
| 서버 로직 | PL/pgSQL 함수 (RPC), 62개 마이그레이션 |
| 인증 | Supabase Auth (카카오 / 전화번호 / 이메일) |
| 배포 | main 브랜치에 푸시하면 GitHub Actions 가 웹 + 앱 업데이트를 자동 배포 |
| 아이콘 | 전부 SVG 로 직접 그림 (해상도 무관, 폰트 아이콘 안 씀) |

**배포 경로가 둘이다**
- **웹(PWA)**: 주소만 알면 설치 없이 쓴다 → 40~60대에게 "앱 설치"라는 장벽을 없앤다
- **설치형 앱**: 태블릿·폰에 설치. 코드를 고치면 앱 재설치 없이 업데이트가 내려간다

## 11. 지금 상태

**돌아가고 있는 것**
- 웹: 라이브 서비스 중
- 서버: 정상, 62개 마이그레이션 적용 완료
- 자동 배포: main 푸시 → 웹 + 앱 동시 배포 (동작 확인됨)
- 운영 계정: 깃허브 · Supabase · Expo 전부 하나의 계정으로 통합 완료

**아직 안 된 것 (알고 있는 것)**

| 항목 | 상태 | 영향 |
| --- | --- | --- |
| **데이터베이스 백업** | 무료 플랜이라 **백업 없음** | 데이터 유실 시 복구 불가 |
| **운동 리마인더 알림** | 코드는 완성, **스위치가 꺼져 있음** | 설정은 저장되나 알림이 안 울림 |
| **구글 로그인** | 앱 코드 완성, 서버 설정 안 켬 | 카카오만 가능 |
| **전화번호 문자 인증** | 문자 발송 기능이 미병합 | 카카오 안 되는 회원 대비책이 없음 |
| **플레이스토어 등록** | 미등록 | 설치형 앱을 일반 배포 못 함 |
| **운동 영상** | 사진만 있음 | 동작 이해도가 사진에 의존 |
| **에러 모니터링** | 없음 | 고장을 회원이 말해줘야 앎 |

## 12. 평가받고 싶은 것

이 문서를 읽고 다음을 봐 주면 좋겠다.

1. **제품 방향** — "아파트 단지 헬스장 + 40~60대"라는 좁은 타겟이 강점인가 한계인가? 확장 경로는?
2. **차별점** — 기존 헬스 앱(플랜핏, 짐워크 등) 대비 실제로 방어 가능한 차별점이 있나? 아니면 쉽게 복제되나?
3. **핵심 기능 우선순위** — 위 「아직 안 된 것」 중 무엇을 먼저 해야 하나? 빠진 기능 중 치명적인 게 있나?
4. **리텐션** — 40~60대가 3개월 뒤에도 쓸 이유가 이 안에 있나? 등급/랭킹/국토종주가 실제로 동기부여가 될까, 아니면 젊은 층 문법의 이식인가?
5. **"화합의 장" 설계** — 응원 게시판을 구조로 제한한 판단(하루 한 줄, 60자, 답글 없음)이 옳은가? 너무 답답한가?
6. **사업 모델** — 관리사무소 대상 B2B 인가, 주민 대상 B2C 인가? 지금 구조가 어느 쪽에 맞나?
7. **혼자 운영하는 리스크** — 개발·운영·영업이 한 사람이고 부업이다. 무엇을 자동화하거나 포기해야 하나?
