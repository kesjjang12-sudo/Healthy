# 카카오에서 전화번호 받기 — 비즈앱 전환 + 권한 심사

키오스크가 회원을 전화번호로 알아보기 때문에, 카카오 로그인으로도 전화번호를
받아야 한다. 전화번호는 카카오의 **심사 대상 동의항목**이라 비즈앱 전환과
권한 신청이 필요하다.

- **심사에 영업일 3~5일**이 걸린다. 그래서 이것부터 신청해 두고 나머지를 하는 게 좋다.
- 사업자등록번호가 필요하다 (준비되어 있음).
- 확인일: 2026-08-18, 카카오 공식 문서 기준.

---

## 지금 어디까지 됐나

| | 상태 |
|---|---|
| Supabase 카카오 제공자 | ✅ 켜짐 (서버에서 확인) |
| 카카오 앱·키·리다이렉트 URI | ✅ 등록됨 |
| 이메일 동의항목 | ⏳ 비즈앱 전환 후 켤 수 있음 |
| **전화번호 동의항목** | ⏳ **비즈앱 + 권한 심사 필요 ← 이 문서** |

> Supabase 는 카카오에 **이메일을 무조건 요청한다.** 그래서 개인 개발자
> 계정에서는 로그인이 `KOE205` 로 실패한다. 비즈앱이 되면 이메일도 켤 수
> 있으므로 이 문제도 같이 풀린다.

---

# 1단계 — 비즈 앱으로 전환 (사업자등록번호)

**앱 관리 페이지 → 앱 → 일반 → 비즈니스 정보**

| 칸 | 넣을 것 |
|---|---|
| 사업자 구분 | 국내 사업자 |
| 사업자등록번호 | 준비하신 번호 |

**저장 → 비즈니스 정보 심사**가 시작된다.

> 심사는 "실제 운영하는 서비스와 이 앱이 같은 서비스인지, 운영정책을 지키는
> 서비스인지"를 본다. 앱 이름(헬스반장)과 사업자명이 실제 서비스와 맞게
> 들어가 있어야 통과가 쉽다.

**사업자등록번호 조회 실패가 뜨는 경우** — 국세청 자료 반영이 늦어서 나는
경우가 있다. 신규 사업자면 며칠 뒤 다시 시도하거나, 카카오 데브톡에 앱 ID 와
함께 문의하면 담당자가 처리해 준다.

---

# 2단계 — 전화번호 권한 신청 (심사 3~5 영업일)

비즈니스 정보 심사가 끝난 뒤에 진행한다.

**앱 관리 페이지 → 앱 → 추가 기능 신청 → 개인정보 동의항목 → 신청**

신청할 항목:

| 동의항목 | 필요한 이유 (심사에 적을 내용) |
|---|---|
| **카카오계정(전화번호)** | 헬스장 입구 키오스크에서 회원을 전화번호로 확인해 출석을 기록하기 위해 |
| **카카오계정(이메일)** | 로그인 시스템(Supabase)이 계정 식별에 사용 |

> 심사에 적는 이용 목적은 **실제 서비스에서 하는 일과 같아야 한다.**
> 위 문장을 그대로 쓰셔도 되고, 실제 동작과 다르면 반려된다.

**반려되면** 사유를 보완해서 같은 자리에서 재신청할 수 있다. 다시 3~5 영업일.

---

# 3단계 — 승인 후 동의항목 켜기

**앱 → 카카오 로그인 → 동의항목**

| 항목 | 설정 |
|---|---|
| 닉네임 | 필수 동의 |
| 프로필 사진 | 선택 동의 |
| **카카오계정(이메일)** | 필수 동의 |
| **카카오계정(전화번호)** | 필수 동의 |

---

# ⚠️ 미리 알아야 할 한계 — 전화번호가 안 오는 사람이 있다

카카오 공식 문서에 있는 제약이다.

> 카카오계정(전화번호)은 **카카오계정에 연결된 카카오톡에서 가져온다.**
> 카카오톡을 쓰지 않는 카카오계정은 전화번호를 받을 수 없다.

즉 **"카카오 로그인 = 전화번호 확보"가 100% 는 아니다.** 카카오톡을 안 쓰는
계정에서는 번호가 비어서 온다.

그래서 지금 있는 두 가지 길을 **없애면 안 된다**:

1. **문자 인증 로그인** — 번호를 직접 인증하므로 가장 확실하다
2. **키오스크 QR 페어링** — 태블릿에서 번호를 찍어 계정과 잇는다

카카오로 번호가 오면 자동으로 이어 주고, 안 오면 기존 방식으로 안내하는
구조가 되어야 한다.

# 앱 코드 쪽에서 할 일 (심사 기다리는 동안 제가 합니다)

승인이 나면 카카오가 전화번호를 주기 시작한다. 그걸 받아 쓰려면 코드도
바뀌어야 한다. 확인해 둔 사항:

- **Supabase 는 추가 권한을 카카오에 그대로 전달한다.** 실제로 시험해서
  확인했다 — `scopes` 를 붙이면 카카오로 가는 요청에 그대로 붙는다.
  따라서 앱에서 `phone_number` 를 요청하면 된다.
- 받은 번호는 `+82 10-1234-5678` 형태로 오므로, 이 저장소의 저장 포맷
  (`01012345678`)으로 바꿔야 한다. 변환은 `local_phone_from_e164` 가 이미 한다.

### 여기서 중요한 설계 판단 하나

**앱이 "내 번호는 010-xxxx-xxxx 야" 하고 서버에 보내는 방식으로 만들면 안 된다.**
그러면 남의 번호를 보내 남의 계정을 가져갈 수 있다. 지금 저장소가 예전에
`sign_in_with_phone`("번호만 알면 로그인")을 지운 이유가 정확히 이것이다
(`20260813000002_claim_account_by_verified_phone.sql` 주석 참고).

그래서 **서버(Edge Function)가 카카오 토큰을 받아 카카오 서버에 직접 물어본 뒤**
그 답으로 계정을 잇는 방식으로 만든다. 클라이언트가 보낸 번호는 믿지 않는다.
